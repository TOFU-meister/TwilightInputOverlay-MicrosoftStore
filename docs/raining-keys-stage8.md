# Raining Keys の描画最適化

## 観測と原因

第7段階の Windows 実機では約545秒で31,148件の Rain テクスチャ生成が観測されました。既存キャッシュは幅、丸めた高さ、幅・高さで制限した角丸半径をキーにします。色、透明度、座標はキーに入りません。伸びるバーと解放後に短くなるバーは複数の高さキーを通るため、キャッシュ上限96件が正常でも生成・退避を繰り返します。ミス時には CPU でマスクのピクセルを生成し、Texture2D の作成、SetPixels32、Apply を実行します。古いエントリーは Destroy を要求します。既存の OnGUI は Repaint でのみ描画しています。

FPS 低下は両プラグインを外した検証でも再現されています。この変更は Rain の独立した描画負荷を減らすものです。

## 描画方式

同じ角丸の距離関数を使い、幅と幅で制限した指定半径から、上端・中央・下端を含む小さなマスクを1枚作ります。高さはキーに含めません。通常の高さでは両端を保ち、中央だけ伸ばします。短いバーでは高さの半分を上限として角を縦横とも縮めます。描画矩形を重ならない領域に分割し、同じ GUI.color と UV 指定で描くことで、半透明色の重複を防ぎます。既存の GUI グループによるクリップ、バーの動き、設定形式と小数精度、半径0の矩形動作は維持しました。

Unity 2019.4 の GUI.DrawTextureWithTexCoords を使用します。手元の Store 用 interop の生成 IL で、Repaint 判定、GUI.color、UV の受け渡しと Graphics.Internal_DrawTexture への委譲を確認しました。通常の角丸バーは最大3描画、短いバーは最大6描画です。旧版は1描画だったため、GPU または Windows 実機での総描画時間は別途計測が必要です。

96件・2,097,152ピクセルの上限、無効参照の検出・再生成、DontUnloadUnusedAsset、明示解放、機能ごとの障害分離を維持しました。ヒットで使用順を更新します。角丸描画に失敗した場合は、未描画のバーと次回以降のバーを矩形へ切り替え、既存の再試行制御に従います。一部を描画したバーへ同じフレームに矩形を重ねません。

## オフライン比較

幅28と56、角丸9.5、0.5px刻みで高さ0.5～160pxを12往復させ、初期準備後の15,360参照を同じ入力で比較しました。旧キャッシュは第7段階のソースを別のスタブ実行環境で使用しました。

| 指標 | 旧 | 新 |
| --- | ---: | ---: |
| 初期準備を含む生成数 | 6,386 | 2 |
| 最後の保持件数 | 96 | 2 |
| 最後の保持ピクセル | 51,744 | 1,764 |
| 最大保持ピクセル | 550,368 | 1,764 |

新方式の自動テストは、領域の合計面積、非重複、UV 範囲、極小高さと最大半径、無効テクスチャとキャッシュ上限を確認します。Windows のラスタライズと半透明の境界は未確認です。

## 実機での確認

1. 角丸0、小さな正の値、幅や高さで制限される大きな値を試します。半透明色で、押下開始直後・長押し・解放・再押下と左右マウスの同時押しを確認します。上端・中央・下端の境界に線や濃度差がないか見ます。
2. マップ移動後、Rain OFF/ON、幅・角丸・色の変更を試し、通常キーと Mouse Overlay が従来どおり動作することを確認します。
3. Debug のパフォーマンス採取を有効にし、overlay-performance.csv の rain_created、rain_count、rain_pixels を比較します。追加列は rain_mask_hits、rain_mask_misses、rain_texture_draws、rain_rounded_fallbacks です。値は累積なので差分を確認します。設定が安定し、高さだけが変化する間は初回以降の生成増加がないことを確認します。長時間の負荷試験は冷却問題への対処後に実施します。
